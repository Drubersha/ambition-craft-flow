# Установка RentFlow на свой сервер — пошагово

Эта инструкция — для полевых испытаний. Всё работает локально на твоём сервере: и приложение, и база данных, и вход (логин/пароль). Никакого облака не нужно.

Все команды нужно копировать **целиком** и вставлять в терминал сервера. Я объясняю что каждая делает, но если просто будешь копировать по порядку — тоже сработает.

---

## Что нужно иметь

- **Сервер** с Ubuntu 22.04 или 24.04 (минимум: 2 ядра CPU, 4 ГБ RAM, 20 ГБ диска).
- **IP-адрес сервера** (например, `203.0.113.42`) — спроси у того, кто дал тебе сервер.
- **Логин и пароль** (или SSH-ключ) для входа на сервер.
- На своём компьютере — терминал: на Windows подойдёт **PowerShell** или **Windows Terminal**, на macOS/Linux — встроенный «Терминал».

Дальше я везде пишу `СЕРВЕР_IP` — заменяй на свой настоящий адрес.

---

## Шаг 1. Заходим на сервер

На своём компьютере открой терминал и выполни:

```bash
ssh ubuntu@СЕРВЕР_IP
```

(если пользователь не `ubuntu`, а, например, `root` — пиши `ssh root@СЕРВЕР_IP`)

Введи пароль. Если всё ок, ты внутри сервера — приглашение в терминале поменяется.

---

## Шаг 2. Ставим Docker

Docker — это программа, которая запускает наши «контейнеры» (приложение и базу). Ставится одной командой:

```bash
curl -fsSL https://get.docker.com | sh
```

Подожди минуту, пока всё скачается. Потом разреши себе пользоваться Docker без `sudo`:

```bash
sudo usermod -aG docker $USER && newgrp docker
```

Проверь, что работает:

```bash
docker --version
docker compose version
```

Должны появиться номера версий. Если так — едем дальше.

---

## Шаг 3. Скачиваем проект

Поставим `git` и `nodejs` (нужен для генерации ключей шагом ниже):

```bash
sudo apt update && sudo apt install -y git nodejs
```

Скачиваем код:

```bash
git clone https://github.com/Drubersha/RentFlow.git
cd RentFlow
```

Теперь ты внутри папки проекта. Все следующие команды выполняются отсюда.

---

## Шаг 4. Создаём файл с настройками

```bash
cp .env.example .env
```

Этот `.env` — это «настройки приложения»: пароли, адреса, ключи. Пока он шаблонный, сейчас будем заполнять.

---

## Шаг 5. Генерируем секретные ключи

Чтобы вход (логин/пароль) был безопасным, нужны три случайных ключа. Они генерируются одной командой:

```bash
JWT_SECRET="$(openssl rand -base64 48)" node scripts/gen-keys.mjs
```

На экране появится что-то вроде:

```
JWT_SECRET=AbCdEf...очень_длинная_строка...XyZ=
ANON_KEY=eyJhbGciOi...очень_длинная...
SERVICE_ROLE_KEY=eyJhbGciOi...очень_длинная...
```

**Скопируй эти три строки целиком** — они понадобятся через минуту. Можешь вставить их в Блокнот на своём компьютере временно.

---

## Шаг 6. Заполняем `.env`

Открой файл настроек:

```bash
nano .env
```

Откроется редактор прямо в терминале. Стрелками двигайся, заменяй значения после `=`. Нужно поменять вот эти строки:

| Строка                           | Что поставить                                  |
| -------------------------------- | ---------------------------------------------- |
| `VITE_SUPABASE_URL=`             | `http://СЕРВЕР_IP:8000` (с твоим настоящим IP) |
| `VITE_SUPABASE_PUBLISHABLE_KEY=` | значение `ANON_KEY` из шага 5                  |
| `SUPABASE_PUBLISHABLE_KEY=`      | то же значение `ANON_KEY`                      |
| `SUPABASE_SERVICE_ROLE_KEY=`     | значение `SERVICE_ROLE_KEY` из шага 5          |
| `POSTGRES_PASSWORD=`             | любой свой надёжный пароль (запомни!)          |
| `JWT_SECRET=`                    | значение `JWT_SECRET` из шага 5                |
| `SITE_URL=`                      | `http://СЕРВЕР_IP:3000`                        |
| `ANON_KEY=`                      | значение `ANON_KEY` из шага 5                  |
| `SERVICE_ROLE_KEY=`              | значение `SERVICE_ROLE_KEY` из шага 5          |
| `DASHBOARD_PASSWORD=`            | любой свой пароль для админ-панели             |

Строку `SUPABASE_URL=http://kong:8000` **не трогай** — это внутренний адрес.

Чтобы сохранить и выйти из `nano`: нажми `Ctrl+O`, `Enter`, потом `Ctrl+X`.

---

## Шаг 7. Запускаем всё

```bash
docker compose up -d --build
```

Первый запуск долгий — 3–7 минут. Docker скачает все контейнеры (база данных, авторизация, приложение) и соберёт твою сборку.

Когда команда закончится, проверь что всё живо:

```bash
docker compose ps
```

Должно быть 5 строк со статусом `running` или `healthy`. Если у какого-то контейнера `restarting` или `exited` — смотри логи (раздел ниже).

### Шаг 7.5. Создаём хранилище для документов

Одна разовая команда — создаёт «корзину» в хранилище файлов:

```bash
docker compose exec -T db psql -U postgres -d postgres <<SQL
INSERT INTO storage.buckets (id, name, public)
VALUES ('documents', 'documents', false),
       ('chat-attachments', 'chat-attachments', false)
ON CONFLICT (id) DO NOTHING;
SQL
```

---

## Шаг 8. Проверяем

Открой в браузере на своём компьютере:

```
http://СЕРВЕР_IP:3000
```

Должна появиться страница входа RentFlow. Нажми **«Зайти в демо режим 1»** (логин `admin`, пароль `admin`) — попадёшь в приложение. Готово, испытания идут!

Если нужен полноценный аккаунт — нажми **«Регистрация»**, придумай email и пароль. Email-подтверждение в этом режиме отключено, можно сразу пользоваться.

---

## Если что-то пошло не так

**Смотрим логи приложения:**

```bash
docker compose logs -f app
```

(выйти из просмотра — `Ctrl+C`)

**Логи базы данных:**

```bash
docker compose logs -f db
```

**Перезапустить всё:**

```bash
docker compose restart
```

**Остановить полностью:**

```bash
docker compose down
```

**Снести всё вместе с базой (если хочется начать с нуля):**

```bash
docker compose down -v
```

⚠️ Удалит все данные!

---

## Полезные мелочи

### Бэкап базы данных

```bash
docker compose exec -T db pg_dump -U postgres postgres | gzip > backup-$(date +%F).sql.gz
```

Файл `backup-2026-06-24.sql.gz` появится рядом. Скачай его себе через `scp` для сохранности.

### Обновление до новой версии

```bash
git pull
docker compose up -d --build app
```

База данных при этом не трогается, обновляется только приложение.

## Безопасность для полевых испытаний

Сейчас порты `3000` и `8000` открыты всему интернету по HTTP — этого достаточно для тестов в локальной сети или закрытого пилота, но **не для публичного запуска**. Минимум что стоит сделать:

1. **Включи firewall** и оставь открытыми только нужное:

   ```bash
   sudo ufw allow OpenSSH
   sudo ufw allow 3000
   sudo ufw allow 8000
   sudo ufw enable
   ```

   Порт `5432` (Postgres) наружу не выставляй — он и так доступен только внутри Docker-сети.

2. **Не используй пароли из шаблона.** В `.env` всё должно быть уникальным — особенно `POSTGRES_PASSWORD`, `JWT_SECRET`, `DASHBOORD_PASSWORD`.

3. **Перед публичным запуском** поставь HTTPS через Caddy или Nginx — пример есть в `README.deploy.md` (раздел «HTTPS через Caddy»).

4. **Email-подтверждение** включается через `GOTRUE_MAILER_AUTOCONFIRM=false` в `.env` + настройка SMTP. Для пилота это не обязательно.
