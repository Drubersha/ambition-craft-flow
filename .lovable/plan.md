## Что добавим

### 1. Папки (только для объектов, договоры наследуют)
- Новая таблица `folders`: `id`, `owner_id`, `parent_id` (для иерархии), `name`, `plan_path` (путь к файлу в Storage), `plan_mime`, timestamps. RLS по `owner_id`.
- В `properties` добавим колонку `folder_id` (nullable — «без папки»).
- Договоры наследуют папку автоматически через `property.folder_id` — отдельного поля у договора нет.

### 2. План территории/объекта
- Файлы (PNG/JPG/PDF) храним в существующем приватном бакете `documents`:
  - План папки: `folder-plans/{folder_id}/{filename}`
  - План объекта: `property-plans/{property_id}/{filename}`
- В `properties` добавим `plan_path`, `plan_mime`.
- Просмотр: изображения — `<img>` по signed URL; PDF — встроенный `<iframe>` + ссылка «Скачать».

### 3. UI

**Раздел «Папки» (`/folders`)**
- Дерево папок слева (раскрываемые узлы), плюс кнопки: создать подпапку, переименовать, удалить (с подтверждением; запрет удаления при наличии объектов/подпапок), переместить.
- Справа: панель выбранной папки — название, загрузка/просмотр/замена/удаление плана, список объектов в этой папке.

**Объекты (`/properties`)**
- Сверху фильтр-селектор папки («Все», «Без папки», конкретные папки с отступом по уровню).
- В форме объекта (новый + редактирование) — поле «Папка» (комбобокс с иерархией) и блок «План объекта» (загрузка/просмотр/удаление).

**Договоры (`/contracts`)**
- Фильтр по папке, который применяется к `contracts.property.folder_id`. Никаких изменений схемы договора.

**Карточка объекта**
- Показываем «хлебные крошки» папки и блок «План объекта».

### 4. Хранилище и доступ
- Используем существующий приватный бакет `documents`. RLS-политики на `storage.objects` для путей `folder-plans/*` и `property-plans/*` — доступ только владельцу (через сопоставление с `folders.owner_id` / `properties.owner_id`).
- Чтение в UI — через `createSignedUrl` (TTL ~1 час).

### Технические детали
- Миграция: `CREATE TABLE public.folders` + GRANT + RLS + политики; `ALTER TABLE properties ADD COLUMN folder_id uuid REFERENCES folders(id) ON DELETE SET NULL`, `plan_path text`, `plan_mime text`; индексы по `folder_id`, `parent_id`; триггер `touch_updated_at`.
- Для иерархического селектора — рекурсивный CTE при загрузке списка папок один раз на сессию (через TanStack Query).
- Удаление папки: проверяем отсутствие детей и объектов на клиенте + защита триггером в БД.
- Перемещение папки: запрет на перенос в собственного потомка (проверка рекурсивным CTE в триггере).

После одобрения создам миграцию, дождусь применения, затем добавлю компоненты `folder-tree`, `folder-picker`, `plan-uploader`, страницу `/folders`, фильтры в списках и поля в формах.
