
## Что делаем

1. Новый раздел сайдбара **«Бюджет»** (`/budgets`) — список папок с их планами расходов, переход в карточку плана.
2. В карточке плана: настройки (день обновления, % предупреждения, статьи расхода с лимитами), ввод фактических расходов по статьям за текущий месяц, история архивных периодов.
3. На дашборде в блок «Управление активами» добавляем 4 показателя: **Расходы за месяц**, **Расходы за год**, **Прибыль за месяц**, **Прибыль за год** — с процентами маржи.

Привязка: один план = одна папка (`folders`). Доходы для прибыли = сумма `payments.amount` за период по договорам объектов этой папки. Глобальный дашборд агрегирует по всем папкам пользователя.

## База данных (новая миграция)

Три таблицы:

- `budget_plans` — один план на папку
  - `id`, `owner_id`, `folder_id` (unique, FK → folders, on delete cascade)
  - `reset_day` smallint 1–28 (день месяца, когда плановый период обнуляется)
  - `warning_percent` numeric(5,2) default 80 (порог предупреждения)
  - `currency` text default 'RUB'
  - `created_at`, `updated_at`

- `budget_categories` — статьи расхода в плане
  - `id`, `owner_id`, `plan_id` (FK → budget_plans, cascade)
  - `name` text, `limit_amount` numeric(14,2), `sort_order` int
  - `created_at`, `updated_at`

- `budget_expenses` — фактические расходы по статьям
  - `id`, `owner_id`, `plan_id`, `category_id` (FK)
  - `amount` numeric(14,2), `spent_at` date, `note` text
  - `period_start`, `period_end` date — границы периода, в котором учтён расход (заполняется автоматически по `reset_day` плана при вставке)
  - `archived` boolean default false (true для прошлых периодов)
  - `created_at`

RLS: на каждой таблице `auth.uid() = owner_id`, политика FOR ALL. GRANT SELECT/INSERT/UPDATE/DELETE → authenticated, GRANT ALL → service_role. Триггеры `touch_updated_at` для plans/categories.

«Архивирование в историю» при наступлении `reset_day`: ставим `archived = true` для всех `budget_expenses` предыдущего периода. Это делаем **лениво на клиенте** при открытии плана — серверный server fn `rolloverBudgetPeriod({ plan_id })` помечает прошлые периоды архивными, если текущая дата вошла в новый период. Никаких pg_cron — пользователь видит актуальный период при заходе.

## Frontend

### Раздел «Бюджет»
- В `src/components/app-shell.tsx`: добавить в `OWNER_NAV` пункт `{ to: "/budgets", label: "Бюджет", icon: Wallet2 }`.
- `src/routes/_authenticated/budgets.index.tsx` — список папок с карточками: название, текущий расход / лимит периода, прогресс-бар, предупреждение если ≥ `warning_percent`. Клик → детали.
- `src/routes/_authenticated/budgets.$folderId.tsx` — детали:
  - Заголовок: имя папки, период (текущий цикл по `reset_day`).
  - Настройки (диалог «Редактировать план»): `reset_day` (Select 1–28), `warning_percent` (Input), таблица статей (имя + лимит, добавить/удалить/изменить).
  - Таблица статей текущего периода: статья | лимит | потрачено | остаток | % | кнопка «Добавить расход» (диалог: сумма, дата, комментарий). Если потрачено > лимита — бейдж «Перерасход» (перерасход разрешён, не блокируем). Если ≥ warning_percent — жёлтый бейдж «Близко к лимиту».
  - Аккордеон «История периодов» — архивные записи, сгруппированные по `period_start`.

### Дашборд
- В `src/routes/_authenticated/dashboard.tsx`, блок «Управление активами» (там сейчас live KPI):
  - Доход_месяц = сумма `payments.amount` за календарный месяц.
  - Доход_год = сумма `payments.amount` за календарный год.
  - Расход_месяц = сумма `budget_expenses.amount` (не архивных + архивных, попадающих в текущий календарный месяц по `spent_at`).
  - Расход_год = аналогично за год.
  - Прибыль_месяц = Доход_месяц − Расход_месяц. Маржа % = Прибыль / Доход × 100 (если доход = 0 → «—»).
  - Прибыль_год = аналогично.
  - 4 карточки в гриде: «Расходы за месяц», «Расходы за год», «Прибыль за месяц (X%)», «Прибыль за год (X%)». Прибыль красная если отрицательная.

### Серверная логика
- Все запросы — через `supabase` напрямую с клиента (RLS), как уже устроено в проекте; отдельные server fn не нужны, кроме `rolloverBudgetPeriod` если решим серверно (можно и на клиенте через UPDATE).
- Хелперы в `src/lib/budget.ts`: `getCurrentPeriod(reset_day, today)` → `{start, end}`, форматирование, расчёт прогресса.

## Технические детали

- Период плана считается от `reset_day`: например `reset_day=5` и сегодня 12 ноября → период `[2024-11-05; 2024-12-04]`. Если сегодня 3 ноября → `[2024-10-05; 2024-11-04]`.
- Дашбордные «месяц/год» — по календарным месяцам/годам (а не по reset_day), чтобы соответствовать формулировке «расходы за месяц/за год».
- Все суммы в `RUB` без мульти-валютности (поле `currency` оставляем на будущее).
- Иконка раздела: `Wallet2` или `PiggyBank` из lucide.

## Что НЕ делаем
- Не подключаем pg_cron — обнуление лениво при открытии.
- Не делаем мульти-валютность и конвертацию.
- Не трогаем существующие таблицы charges/payments/contracts.
