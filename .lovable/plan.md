## Цель
Переписать страницу `src/routes/_authenticated/dashboard.tsx` так, чтобы она соответствовала ТЗ «Дашборд по аренде коммерческой недвижимости» — 5 блоков, глобальные фильтры, цветовое кодирование. Без изменений схемы БД и без новых таблиц.

## Что есть в данных сейчас
- `properties` (area_total, base_rate, status, type, currency)
- `contracts` (rate, area, start/end_date, status, currency)
- `charges` (period_start/end, total, paid_total, status, due_date)
- `payments` (amount, paid_at, method)
- `tenants` (name, …)

## Что в ТЗ отсутствует в БД — будет помечено заглушкой «нет данных»
- Операционные расходы → блок «NOI» и «Операционные расходы» покажем как заглушку с подписью «нет данных»
- План vs Факт по доходу → заглушка
- Воронка новых арендаторов (лиды/просмотры/переговоры) → заглушка
- История индексаций ставок → показ из истории `contracts.rate` по property (если несколько договоров по объекту), иначе пусто
- Ответственный менеджер → фильтр скрыт (нет поля)
- SSO/RBAC/аудит → вне scope этой задачи

## Структура новой страницы

### Шапка
- Заголовок «Дашборд»
- Панель глобальных фильтров (применяются ко всем блокам через `useState`+`useMemo`, без перезагрузки):
  - Период: `день / месяц / квартал / год / произвольный` (диапазон через date input)
  - Объекты: мультиселект
  - Тип объекта: офис/ритейл/склад/производство (на основе enum `property_type`)
  - Статус объекта: в аренде / частично / вакантен
- Активные фильтры — чипами; кнопка «Сбросить все»
- Подпись «Обновлено: <время загрузки>»

### Блок 1. Портфель — KPI (карточки)
- Общая площадь портфеля (Σ `area_total`)
- Количество объектов
- % занятости = Σ(area арендованных по активным договорам) / Σ area_total · цвет ≥90 зел / 70–89 жёлт / <70 красн
- Арендный доход за период (Σ `payments.amount` где `paid_at` в периоде)
- Средняя ставка (взвешенная по площади активных договоров, руб/м²/мес)
- Просроченная дебиторка > 30 дней (Σ остатков по charges со статусом overdue/partial/unpaid и due_date старше 30 дней) — красный маркер
- Договоры, истекающие в ближайшие 90 дней — с предупреждением

### Блок 2. Объекты и помещения (таблица)
Колонки: Название (ссылка → `/properties/$id`), Тип, Общая площадь, Занятость % (Progress + цвет), Ставка (`base_rate` или средняя по активным договорам), Ежемес. доход (Σ rate×area активных договоров / период), Статус (Badge).
Сортировка по любой колонке (клик в заголовок), поиск по названию.

### Блок 3. Договорная база
- Кольцевая диаграмма статусов договоров (recharts PieChart) — active/expiring/draft/terminated
- Три списка: «истекают 0–30», «31–60», «61–90 дней» (по `end_date` активных)
- История индексаций ставок: таблица по property — старая ставка → новая ставка (вычисляется из последовательности договоров по property, сортированных по start_date)
- Воронка арендаторов — placeholder с подписью «нет источника данных»

### Блок 4. Дебиторская задолженность
- Карточка: общий объём дебиторки (Σ total-paid_total по непогашенным)
- Aging — столбчатая (BarChart): 0–30 / 31–60 / 61–90 / >90 дней
- Коэффициент сбора: Σ paid / Σ billed за период
- Таблица должников: арендатор, объект, сумма долга, максимальная просрочка
- История платежей — последние 20 (дата, сумма, арендатор, метод)

### Блок 5. Финансовые показатели
- Динамика арендного дохода — LineChart по месяцам за выбранный период (группировка `payments.amount` по `date_trunc('month', paid_at)`)
- NOI — карточка + график: заглушка «нет данных об операционных расходах»
- Вакантность по типу объекта — горизонтальный BarChart (по `property.type` считаем % свободной площади)
- План vs Факт — заглушка
- Операционные расходы — заглушка

## Технические детали
- Один файл `src/routes/_authenticated/dashboard.tsx` (полное переписывание).
- Один общий `useQuery(['dashboard-raw'])` грузит `properties`, `contracts(+tenant,+property)`, `charges`, `payments(+charge+contract)` — затем всё считается из `useMemo` с применением фильтров на клиенте. Объём данных у одного арендатора небольшой — это безопасно.
- Графики: уже установленный `recharts` через `@/components/ui/chart`.
- Цветовая палитра: только semantic токены (`--primary`, `--destructive`, добавлю `--success` и `--warning` в `src/styles.css` если их нет, плюс соответствие в Tailwind через CSS-переменные).
- Адаптив: grid `grid-cols-1 md:grid-cols-2 xl:grid-cols-4` для KPI, таблицы со `overflow-x-auto`.
- Без изменений серверного кода, миграций, роутинга.
