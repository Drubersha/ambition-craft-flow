## Что добавляем

На странице **Начисления** (`/charges`) рядом с заголовком появится кнопка **«Авторасчёт начислений»**. По клику:

1. Загружаются все активные договоры (`status = 'active'`, `kind = 'rent'`).
2. Для каждого договора разбивается период от `start_date` (но не раньше начала договора) до текущего месяца включительно на отрезки по `payment_period`:
   - `monthly` — по календарным месяцам
   - `quarterly` — по календарным кварталам
   - `yearly` — по календарным годам
   - `one_time` — один период от начала до конца договора (если ещё нет ни одного начисления)
3. Для каждого отрезка проверяется, есть ли уже начисление с таким же `period_start` у этого договора. Если нет — создаётся новое, сумма считается формулой `chargeTotalForPeriod(rate, payment_period, period_start, period_end, area)` (та же, что используется в ручном «Начислить»).
4. Если `end_date` договора попадает внутрь периода — `period_end` подрезается датой окончания.
5. `due_date` ставится равной `period_end`.
6. Договоры с `kind = 'ahch'` пропускаются.

Перед массовой вставкой показывается подтверждение с количеством будущих новых начислений: «Будет создано N начислений по M договорам. Продолжить?». После вставки — toast «Создано N начислений», список обновляется.

Если новых нет — toast «Все начисления уже на месте».

## Где меняется код

- `src/routes/_authenticated/charges.index.tsx` — добавить кнопку в шапку, новый компонент `AutoChargesButton` с диалогом подтверждения и мутацией.
- Логика разбиения периодов — небольшая утилита прямо в этом же файле (или в `src/lib/format.ts` рядом с `chargeTotalForPeriod`, если так чище). Никаких изменений БД и серверных функций не требуется — всё через клиентский `supabase` с RLS.

## Что НЕ входит

- Не трогаем существующий ручной диалог «Начислить» в карточке договора.
- АХЧ-договоры в авторасчёт не попадают.
- Никаких миграций, новых таблиц, edge-функций.
