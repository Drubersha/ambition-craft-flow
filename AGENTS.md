## Cursor Cloud specific instructions

LeasePlease/RentFlow is a single-product app: a TanStack Start (React 19 + Vite 8) SSR frontend with a Supabase backend. There is only one service to run.

- Package manager is **bun** (see `bun.lock`, `bunfig.toml`); do not use npm/yarn. The dev server runs at `http://localhost:8080` via `bun run dev` (port is set by `@lovable.dev/vite-tanstack-config`, not in `vite.config.ts`).
- Standard scripts live in `package.json`: `bun run dev`, `bun run lint`, `bun run typecheck`, `bun run test` (vitest), `bun run build`.
- The committed `.env` points `VITE_SUPABASE_URL` / `SUPABASE_URL` at the hosted **Lovable Cloud Supabase** project. `bun run dev` connects to that real cloud DB (already seeded), so no local Supabase/Docker is needed for normal development. The `docker-compose.yml` + `README.deploy.md` describe an optional fully self-hosted stack and are NOT required to develop.
- Auth: the `/auth` page has demo buttons. "Зайти в демо режим 1" opens a gate (login/password default `admin`/`admin`, from `DEMO_GATE_*` env) then signs in as the seeded owner demo account (`demo@rentflow.local`). This is the quickest way to reach an authenticated dashboard with data. Demo "режим 2" auto-wipes its data on logout. Privileged demos (moderator/developer) require server env (`DEMO_PRIVILEGED_ENABLED=1`) and are disabled by default.
- `src/routes/routeTree.gen.ts` is auto-generated by the router plugin; do not edit by hand. Routing is file-based under `src/routes/` (see `src/routes/README.md`).
- `bun run lint` currently passes with 0 errors but ~200 pre-existing `no-explicit-any` warnings; warnings are expected.
- Server functions read server-only secrets from `process.env` (bun auto-loads `.env`). The committed `.env` only has the public `SUPABASE_URL`/`SUPABASE_PUBLISHABLE_KEY`, so the following are NOT present by default and must be supplied (e.g. as Cursor secrets) to exercise those features against the hosted Supabase:
  - `SUPABASE_SERVICE_ROLE_KEY` — required by the admin client (`client.server.ts`). Without it, ALL chat and task server functions fail (e.g. opening any chat throws `Missing Supabase environment variable(s): SUPABASE_SERVICE_ROLE_KEY`). The error is console-only; the UI silently fails to open the chat.
  - `LOVABLE_API_KEY` — required by `analyzeMessage` (`tasks.functions.ts`) for AI photo/text analysis of tenant messages. Without it, analysis returns `no_key` and no task suggestion is created. Owners can still use the manual "В задачи" button (`createManualTaskFromMessage`), which does not call the AI.
  - The dev server reads these at process start, so restart `bun run dev` after the env changes.
